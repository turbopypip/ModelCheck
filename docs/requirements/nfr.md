# Нефункциональные требования

cp1 · предложено к согласованию · владелец каждой записи — Кочкин Денис Сергеевич · приоритет Must. Фактические значения появятся после реализации. Коды проверок обозначают будущие протоколы в docs/quality/. Схемы и ADR с привязкой к указанным компонентам входят в КТ‑2.

| ID · область | Основание | Метрика и порог приёмки | Условия и метод проверки |
|---|---|---|---|
| NFR-001 · задержка отчёта | BR-001, US-001, US-003, US-004. Покупатель ждёт ответ перед заказом | p90 от отправки URL до содержательного отчёта ≤60 с | PERF-01: 60 разных сохранённых карточек, 2 одновременных запроса, 2 vCPU / 4 ГБ, пустой кеш, ответы поиска и модели воспроизводятся с фиксированной задержкой 2 с каждый. Статусы ошибки считаются превышениями; живую задержку измерить отдельно |
| NFR-002 · идентификация | BR-002, US-002. Ошибка версии искажает весь отчёт | Верная модификация у ≥90% однозначных карточек; 0 уверенных присвоений на контрольных неоднозначных примерах | QUAL-01: 60 отложенных карточек по плану паспорта и минимум 5 отдельных неоднозначных примеров. Сверка с заранее зафиксированной разметкой; отдельно указать знаменатели |
| NFR-003 · обоснованность замечаний | BR-002, US-003. Покупатель проверяет причину | Точность ≥85%, полнота ≥75%; у 100% конфликтов есть обе исходные строки и ссылки | QUAL-02: на той же отложенной выборке считать по парам «товар, атрибут». TP — верно названный конфликт, FP — ошибочное предупреждение, FN — пропуск. Точность TP/(TP+FP), полнота TP/(TP+FN). При пустом знаменателе метрика не измерена. Указать число случаев и результаты синтетических примеров отдельно |
| NFR-004 · отказы | BR-001, US-001, US-003. Неопределённость должна быть видна | Все 4 случая дают конечный статус с причиной за ≤65 с | FAIL-01: имитировать отказ магазина, поиск без результата, тайм-аут модели и некорректный ответ модели. Проверить отсутствие вывода о подлинности и сохранение уже извлечённых данных |
| NFR-005 · конфиденциальность и граница доступа | BR-001, US-001, US-004. Отчёт относится к сессии покупателя | 100% запросов чужого отчёта отклонены; обработчик URL обращается только к публичным HTTP(S)-ресурсам | SEC-01: две сессии, чтение и сравнение своего и чужого отчёта; проверка адреса до запроса и при переадресации по тестовой матрице публичных и внутренних назначений |
| NFR-006 · наблюдаемость | BR-001, US-001. Нужна диагностика задержек | В 100% из 20 прогонов есть ID, этап, длительность и конечный статус; в журнале отсутствуют секреты и параметры пользовательского URL | OBS-01: по 10 успешных и отказных запросов, проверка структурированных записей по ID |
| NFR-007 · запуск и обновление | BR-001, US-003. Приёмка воспроизводима | 2 из 2 запусков на чистом стенде дают один ожидаемый отчёт для контрольной карточки | OPS-01: сборка из тега, миграции, фиксированные снимки и тестовый режим модели. Отдельно выполнить обновление с сохранением ранее созданного отчёта |
| NFR-008 · бюджет модели и поиска | BR-001, US-002. Цена одной проверки ограничена | ≤3 обращений к модели и ≤3 поисковых запросов на карточку, включая повторы. Исчерпание бюджета даёт частичный отчёт | AI-01: 10 входов с работающими и недоступными источниками; по журналу собрать число вызовов, версию модели и шаблона, входные и выходные токены. Денежную стоимость рассчитать по тарифу выбранного поставщика на дату испытания |
| NFR-009 · сохранность отчётов | BR-002, US-003. Можно повторно открыть основания | При восстановлении из контрольной копии доступны все отчёты, записанные до её создания; восстановление ≤10 минут | REC-01: 100 сохранённых отчётов, чистая БД на стенде 2 vCPU / 4 ГБ. Сравнить IDs, источники и значения с исходным снимком |
| NFR-010 · сопровождаемость | BR-002, US-001, US-003. Изменения парсера проверяются до поставки | Для каждого из двух адаптеров есть автоматическая проверка нормальной и изменённой разметки; нарушение ожидаемого результата блокирует сборку | CI-01: 4 фиксированных входа, запуск в CI на изменении адаптера, контрольный отрицательный прогон |
